# Небесный дракон — контекст проекта

Личное приложение владельца для личностного роста в стиле тёмного восточного фэнтези: трекер жизни в виде небольшой игры плюс честная статистика. Один пользователь. Должно работать на ПК и телефоне; позже — Telegram-бот.

**Актуальная мобильная версия: https://evgenmak-coder.github.io/My-app/** — владелец просил давать эту ссылку в каждом ответе, где что-то изменено или отправлено на GitHub (адрес постоянный, при обновлениях не меняется). Перед этим проверять, что сборка в Actions прошла и нужное изменение действительно есть на сайте.

Общение с владельцем — на русском. Он не веб-разработчик: объяснять простыми словами, решения по дизайну и механике принимать самому и показывать результат — он поправит. Код, комментарии и интерфейс — на русском.

## Команды

```bash
npm run dev     # сервер разработки, http://localhost:5173 (с ключами в .env.local — облако, нужен вход)
npm run dev:local   # то же без облака, порт 5174: данные в браузере, вход не нужен — для проверок Claude
npm run test    # vitest: правила игры (src/game)
npm run build   # tsc --noEmit + сборка в dist/
python scripts/import_excel.py "путь/к/Небесный дракон.xlsx"   # Excel → seed.local.json
npm run migrate # выполнить в Supabase новые файлы из supabase/migrations (нужен SUPABASE_ACCESS_TOKEN в .env.local)
python scripts/migrate.py --status   # только показать, что выполнено
```

В новом терминале Node может быть не в PATH (ставился через winget) — тогда добавить `C:\Program Files\nodejs`.

## Стек

Vite + React 18 + TypeScript, react-router (HashRouter — нужен для GitHub Pages), @tanstack/react-query, three (только витрина титанов), vite-plugin-pwa, vitest. Стили — обычный CSS с токенами, без UI-библиотек. Графики (колесо жизни, кольцо долей, линия роста) — свой SVG в `components/RadarWheel.tsx` и `components/charts.tsx`; библиотеку recharts убрали, она весила почти половину приложения. Анимации фона и дракона — Canvas 2D, написаны вручную.

## Устройство кода

- `src/game/` — чистые правила без React, покрыты тестами в `game.test.ts`:
  - `xp.ts` — опыт («ци») и 9 стадий дракона
  - `ranks.ts` — ранги навыков по значению 0–100
  - `titans.ts` — материалы титанов, герои
  - `goals.ts` — 5 уровней важности целей, награды, цвета
  - `treasury.ts` — категории денег, месяцы, доли расходов, выплаты
  - `countdown.ts` — отсчёт дней и часов до даты, склонения, мысли дня
  - `wishes.ts` — желания: дни до срока, порядок списка, сумма цен
- `src/data/` — хранение:
  - `types.ts` — все типы, `Snapshot` (весь набор данных), `normalizeSnapshot` (дополняет старые данные новыми полями), `parseImport`
  - `store.ts` — интерфейс `DataStore` (примитивы хранения)
  - `localStore.ts` — localStorage; `supabaseStore.ts` — Supabase
  - `index.ts` — выбирает хранилище: Supabase, если заданы ключи в `.env.local`, иначе localStorage
  - `actions.ts` — вся игровая логика поверх `DataStore` (начисление опыта, история, пересчёты)
  - `hooks.ts` — `useSnapshot`, `useAction`, `useSession`. `useAction` обновляет экран сразу: действие сначала проигрывается на копии данных в памяти (`MemoryStore`), настоящее сохранение и сверка с облаком идут следом, при ошибке экран откатывается
- `src/fx/` — холст и звук: `dragon.ts` (процедурный дракон), `effects.ts` (фоновые эффекты стихий), `sound.ts` (звук стихий, синтез через Web Audio, без файлов), `statues.ts` (объёмные статуэтки титанов из простых тел) и `titanStage.ts` (сцена three.js: круг, свет, материалы, листание), `util.ts`
- `src/theme/` — `tokens.css` (палитра и стихии), `global.css` (все стили), `appearance.ts` (стихия, интенсивность, звук, громкость, фон — хранятся на устройстве, не синхронизируются)
- `src/components/` — `Dragon`, `Atmosphere`, `RadarWheel`, `Talisman`, `WishCoin`, `TitanCarousel` (витрина статуэток, грузится отдельным куском), `ui.tsx` (`Panel`, `Bar`, `RankBadge`, `DataGate`)
- `src/features/<раздел>/` — страницы
- `supabase/migrations/` — SQL по порядку номеров. Выполняет `scripts/migrate.py` (через Management API Supabase, по токену владельца из `.env.local`; журнал — таблица `schema_migrations`). Владелец разрешил Claude запускать его самому после добавления новой миграции. Миграции только добавляют таблицы и столбцы; всё, что удаляет или меняет данные, — сначала спросить. Без токена — как раньше: дать владельцу SQL, он выполняет вручную в SQL Editor

### Как добавить новый раздел с данными

1. Типы и поле в `Snapshot` в `types.ts`; пустое значение в `emptySnapshot`, `normalizeSnapshot`, `snapshotFromSeed`.
2. Методы в `DataStore`, реализовать в `localStore.ts` и `supabaseStore.ts` (загрузка, запись, `replaceAll`).
3. Новая миграция `supabase/migrations/000N_*.sql`: таблица с `user_id default auth.uid()`, RLS-политика `own_rows`. Если появился новый источник опыта — обновить check-ограничение `xp_events_source_check`.
4. Логика — в `actions.ts`, чистые расчёты — в `src/game/` с тестами.
5. Страница в `src/features/`, маршрут в `src/app/App.tsx`, пункт меню в `Layout.tsx`.
6. При необходимости — чтение листа в `scripts/import_excel.py`.

## Механики

- **Опыт (ци)**: 10 за пункт навыка, 5 за пункт сферы, 10 за пункт титана, деяния вручную (10–100), цели при завершении (500/300/200/100/50 по уровням). Только за рост; откат ничего не отнимает. Казна опыта не даёт.
- **Дракон**: 9 стадий (0, 100, 300, 700, 1500, 3000, 5000, 8000, 12000 ци), растёт и внутри стадии. Стадии идут по китайскому канону из `DRAGON_REFERENCE.md` (файл владельца, его ТЗ на дракона): яйцо → хуэй 虺 (змейка) → цзяо 蛟 (лапы) → лун 龍 (усы, грива, рожки, нарост чи-му) → цзяо-лун 角龍 (оленьи рога, 5 когтей) → ин-лун 應龍 (крылья, жемчужина); между каноническими — промежуточные «старшие». Крылья только на последней стадии.
- **Как нарисован дракон** (`fx/dragon.ts`): один процедурный дракон, части включаются по таблице `LOOKS`. Вид сбоку: спина в чешуе, брюшные щитки, гребень, лапы, голова в профиль. Спина всегда тянется вверх экрана (`tw` — поворот вокруг оси): на разворотах тело перекручивается, а голова на миг показывается сверху. Тело рисуется кусками от хвоста к голове, чтобы кольца ложились друг на друга. На узком экране «камера» отходит по мере роста (`frame()`).
- **Навыки**: ранги с границами 21 / 51 / 71 / 96 (как в Excel): Ученик, Адепт, Мастер, Старейшина, Небожитель.
- **Титаны**: Сила — Викинг, Ловкость — Зоро (самурай трёх мечей), Выносливость — Спартанец, Взрывная выносливость — Тодзи, Растяжка — Алукард (Хеллсинг). Каждый — объёмная статуэтка, вылепленная кодом. `fx/statues.ts`: скелет на суставах задаёт позу; тело и лицо лепятся одним куском без швов (`fx/sculpt.ts` — поле расстояний из мягко сливающихся комков, поверхность снимается «шагающими кубиками», то же поле даёт тени в складках через цвет вершин); одежда, доспехи и оружие — отдельные детали (`drape` — ткань в складку, `plate` — выдавленные клинки); в конце всё сплавляется в две сетки на статуэтку. Волосы, борода и кимоно лепятся так же (`r.later`). Лепка одной фигуры — около 0,1 с на компьютере, поэтому все пять лепятся заранее, под заставкой при входе в приложение (`app/Preloader.tsx`), и хранятся до конца сеанса; сцена витрины одна на всё приложение (`sharedStage`) и не пересоздаётся при переходах между разделами — владелец просил, чтобы переключение разделов было без подгрузок, ждать он согласен только при входе, отлитая из материала титана (фактура — волокна дерева, чеканка и патина металла, прожилки нефрита — считается в шейдере `surface()` в `titanStage.ts`, без картинок-текстур): дерево, бронза, серебро, золото, нефрит — меняется каждые 20 пунктов. Статуэтки стоят по кругу, круг листается пальцем, стрелками или касанием края; статуэтка в центре — выбранный титан, тренировка записывается ему. Спартанец и викинг сделаны по `CHARACTERS_REFERENCE.md` владельца (гребень поперёк, без лямбды; шлем с «очками», без рогов). Раньше были картинки в `public/titans/` — они лежали только на компьютере владельца (чужие изображения в публичный репозиторий не кладём), поэтому на телефоне не показывались; больше не используются.
- **Сфера «Спорт»** считается сама как среднее по титанам, ползунок заблокирован. Остальные сферы — вручную.
- **Цели**: уровни Звёздный, Небесный, Горный, Земной, Речной (от самого жёсткого). Цель — талисман (узел, монеты на шнуре, кисть): монет 5/4/3/2/1 по уровням, прогресс делится между монетами поровну и зажигает их сверху вниз, частично заполненная горит вполсилы (`coinGlow`); цвет цели — цвет шнура. Раньше были сосуды с жидкостью — владельцу не подошли по стилю. Нажатие на правую половину талисмана +5%, на левую −5%. Опыт за цель выдаётся один раз (`rewarded`).
- **Казна**: расходы — Медицина, Игры, Техника, Еда, Квартира, Развлечения, Прочее (список задаёт владелец, лишних не добавлять). Платёж по кредиту уменьшает долг и в расходы не попадает.
- **Подписки**: название, сумма, число месяца. В расходах идут своей долей «Подписки» отдельного цвета (`SUBSCRIPTION_CATEGORY`), вручную эта категория не выбирается. Отдельных записей в журнале не создают — списание вычисляется (`chargeIn` в `treasury.ts`) и попадает в расходы, доли и свиток месяца только с дня списания. Считается с начала месяца, в котором подписку добавили. Отмена (×) переносит в архив, прошлые списания остаются; ни разу не списанная удаляется сразу. Новая цена действует с текущего месяца: старая запись закрывается и уходит в архив, прошлые месяцы не пересчитываются.
- **Грядущее** (главная): название и дата; идёт отсчёт в днях и часах до начала этого дня, обновляется раз в минуту. Ближайшие сверху, прошедшие («прошло N дней») — внизу, пока владелец их не уберёт. Добавление и удаление спрятаны за неприметной кнопкой «＋ день» — владелец просил, чтобы она не бросалась в глаза. Мысль дня — одна на сутки из списка `WISDOM`.
- **Желания**: название, цена (0 — не указана) и срок — на выбор «Без срока» или «К дате». У каждого желания монета — насколько сильно хочется: бронза, серебро, золото, нефрит (`WISH_LEVELS`, `components/WishCoin.tsx`). У металлов чины: мандаринское 官, княжеское 侯, королевское 王, императорское 皇 желание — владелец назвал «баронское, графское, королевское, императорское» и разрешил два младших переложить на китайский лад. Монета же служит галочкой: нажатие переносит желание во вкладку «Исполнено», повторное — возвращает. Металл выбирается при добавлении и меняется у готового желания в режиме правки. Сверху сумма цен списка. Порядок: от нефрита к бронзе, внутри металла — со сроком от ближайшего, затем бессрочные. Добавление и удаление спрятаны за неприметной кнопкой «＋ желание», как в «Грядущем». Опыта не дают и с казной не связаны — владелец просил только список.
- **Стихии**: Пламя, Кровь, Гроза, Тень — цвет акцента и свой фоновый эффект; интенсивность Выкл / Спокойно / Обычно / Буйство. Огонь — частицы (без `ctx.filter`, его нет в Safari на iPhone).
- **Звук стихий** (по умолчанию выключен, включается в Настройках): Гроза — дождь и гром вслед за молниями на экране, Пламя — огонь, барабаны и лязг клинков, Тень — тревожный гул; у Крови звука нет (владелец просил пока не трогать). Эффекты сообщают звуку о событиях через `soundscape.trigger`.

## Дизайн

## Что не сделано и что известно

- **Supabase подключён**: проект создан, миграции 0001–0008 выполнены, регистрация закрыта, ключи лежат в `.env.local` и в секретах GitHub; сайт на Pages собран с ними, владелец открывает его на iPhone как PWA. Сам вход и запись в облако Claude проверить не может (пароль вводит только владелец) — если что-то ломается, просить скриншот.
- Приложение на телефоне — установленное PWA и хранит свою копию сайта. Обновления ищет `src/pwa.ts` (при запуске, при возврате в приложение, раз в полчаса) и сам перезагружает страницу; в Настройках видна дата сборки и есть кнопка «Обновить приложение». Если владелец говорит «на телефоне ничего не изменилось» — сначала сверить дату сборки в Настройках.
- После отправки нескольких сборок подряд не перезапускать старые запуски в Actions: они вытесняют друг друга. Нужна только последняя, либо кнопка «Run workflow».
- Общая формула финансового состояния и связь сферы «Деньги» с казной — ждут формулировки от владельца.
- Счета, инвестиции и план бюджета по датам из Excel не перенесены.
- Нет редактирования уровня цели и связи «задачи внутри цели»; нет удаления записей журнала тренировок.
- «Список счастья» (награды за очки из Excel) не начат; Telegram-бот — в самом конце.
- Дракон нарисован кодом (в версии 1.3.0 переписан в профиль по канону). Дальше улучшать можно так: трёхмерная модель (в `DRAGON_REFERENCE.md` есть ссылки на модели CC-BY — скачивает владелец, нужен three.js) или его собственные картинки по стадиям. Пиксельные спрайты из того же файла не подходят по стилю.
- Плавность анимаций на телефоне и сам звук на слух не проверялись: встроенный браузер Claude тормозит анимацию и не воспроизводит звук для проверки.
- `npm audit` сообщал об уязвимостях в зависимостях — не разбирались.
- Оптимизация (версия 1.5.1): главный файл приложения 979 → 556 КБ, анимации дракона и витрины останавливаются, когда прокручены за край экрана. Не сделано: каждое действие всё ещё перечитывает из облака все таблицы целиком (экран уже не ждёт, но трафик идёт); история загружается вся без ограничения по времени — станет заметно через годы.
- Сервер разработки иногда отдаёт устаревший модуль после нескольких быстрых правок подряд (пустой экран, ошибка HMR) — лечится перезапуском `npm run dev`.
